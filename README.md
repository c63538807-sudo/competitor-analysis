# Competitor Analysis Automation

## 项目简介

Competitor Analysis Automation 是一个面向 AI Chat 产品竞品分析场景的自动化工作流项目，旨在将原本需要大量人工完成的竞品测试、回答整理、质量分析、Excel 填写及日报生成等工作逐步自动化，提升竞品分析效率并保证分析结果的一致性。

本项目采用模块化设计，将整个工作流拆分为多个独立模块，便于持续迭代与扩展。

---

# 项目背景

目前，每日竞品分析工作主要包含以下步骤：

1. 从真实用户聊天记录中筛选具有代表性的测试问题。
2. 在多个 AI 产品中进行测试并获取回答。
3. 整理各竞品回答及截图。
4. 对回答质量进行分析与对比。
5. 填写竞品分析 Excel 模板。
6. 输出每日竞品分析总结。

上述流程涉及大量重复性的复制、粘贴、截图、整理及分析工作，整体耗时较长，也容易因人工操作导致数据遗漏或分析标准不一致。

本项目希望通过 Agent 自动化完成绝大部分重复劳动，仅保留人工进行实际竞品测试。

---

# 项目目标

最终构建一套完整的竞品分析自动化平台，实现：

- 自动获取每日测试问题
- 自动生成每日测试任务
- 手机端快速采集竞品回答
- 自动整理测试数据
- 自动进行事实校验
- 自动分析各模型回答质量
- 自动填写竞品分析 Excel
- 自动生成每日竞品分析报告
- 沉淀历史数据并支持趋势分析

整个流程应尽可能减少人工操作，提高效率，并保持分析标准一致。

# 各模块职责

负责说明：

- 每日工作流程
- 数据流转
- 开发阶段
- 模块之间关系

---

## Collector

负责竞品回答采集。

功能包括：

- 展示每日测试问题
- 录入各竞品回答
- 上传回答截图

---

包括：

- 回答质量评价

- 优化建议

---

## Report

包括：

- AIC Chat效果竞品对比
- 竞品分析具体问答

---

- 日报管理
- 周趋势
- 月趋势
- 能力变化分析
- Dashboard

# 开发原则

整个项目开发过程中，应始终遵循以下原则。

## 模块职责单一

每个模块仅负责自己的工作。

例如：

- Collector 仅负责采集数据。
- Analysis 仅负责分析数据。
- Report 仅负责生成报告。

避免职责重叠。

---

## 自动化优先

凡是可以程序完成的重复工作，应优先自动化。

减少人工复制、粘贴、截图、整理等操作。

---

## 数据统一

所有模块统一使用标准 JSON 数据结构进行交互。

避免模块之间直接依赖 Excel。

Excel 仅作为最终输出。

---

## 模板优先

所有 Excel 输出均应基于 templates 中的标准模板生成。

不得创建新的模板格式。

不得修改模板列结构。

---

## 可扩展设计

项目应保持模块化，方便未来增加：

- OCR 自动识别
- Prompt 自动抓取
- Dashboard
- 云同步
- 多人协作
- 历史统计

无需重构整体架构。

---

## 客观分析

所有评价均应基于真实回答内容。

涉及事实、新闻、时间、数学等内容时，应优先联网验证，不依赖模型记忆。

---

# Agent 工作约定

Claude Code 在开发过程中应遵循以下约定：

1. 优先阅读 README.md 和 WORKFLOW.md，理解项目整体结构。
2. 根据对应模块需求（docs）进行开发。
3. 所有输出遵循 templates 中的标准模板。
4. 不修改模板，仅生成新的输出文件。
5. 保持项目模块解耦，避免跨模块实现功能。
6. 新增功能时优先复用现有架构，而非重复实现。

---

# 最终目标

构建一个覆盖：

**问题获取 → 竞品回答采集 → 自动分析 → Excel 填写 → 日报生成 → 历史趋势分析**

的完整竞品分析自动化平台。

通过持续迭代，使每日竞品分析流程尽可能自动化，仅保留必要的人工测试环节，为产品优化提供更加稳定、客观、可追溯的数据支持。
