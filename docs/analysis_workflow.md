# Analysis 模块执行流程设计文档

**版本**: v1.0
**状态**: 设计阶段（尚未开发）
**前置文档**: `docs/analysis_prd.md`（产品设计）
**输入**: `today.json`
**输出**: `analysis_result.json`

---

## 1. 整体 Workflow

```
                        ┌─────────────────────┐
                        │     today.json       │
                        │  (Collector 输出)     │
                        └──────────┬──────────┘
                                   │
                                   ▼
                        ┌─────────────────────┐
                        │   Step 1: 读取 & 解析  │
                        │   校验文件结构完整性     │
                        └──────────┬──────────┘
                                   │
                                   ▼
                        ┌─────────────────────┐
                        │   Step 2: Question    │
                        │   Loop 入口           │
                        │   遍历每道题           │
                        └──────────┬──────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    │              │              │
                    ▼              ▼              ▼
              Question 1     Question 2     Question N
                    │              │              │
                    └──────────────┼──────────────┘
                                   │
                                   ▼
                        ┌─────────────────────┐
                        │   Step 3: Daily       │
                        │   Summary 汇总         │
                        └──────────┬──────────┘
                                   │
                                   ▼
                        ┌─────────────────────┐
                        │   Step 4: 输出        │
                        │   analysis_result.json│
                        └─────────────────────┘
```

### 各步骤职责

| 步骤 | 输入 | 输出 | 说明 |
|------|------|------|------|
| Step 1: 读取 & 解析 | `today.json` 文件路径或内容 | 结构化 Session 对象 | 校验 `date`、`questions`、`competitorMeta` 字段存在且合法 |
| Step 2: Question Loop | Session 对象 | 每道题的完整分析结果 | 逐题执行全部分析子步骤（见 §2） |
| Step 3: Daily Summary | 所有题的分析结果 + competitorMeta | `dailySummary` 对象 | 跨题统计 + 洞察提炼（见 §9） |
| Step 4: 输出 | Session + 分析结果 + dailySummary | `analysis_result.json` | 叠加写入，保留原始数据（见 §10） |

### 每步输入输出

| 子步骤 | 输入 | 输出 | 写入字段 |
|--------|------|------|----------|
| 2.1 读取回答 | question 对象 | AIC文本 + 竞品列表 | — |
| 2.2 Fact Check | 问题 + 回答文本 | `fcResult` 对象 | `analysis.factCheck` |
| 2.3 Quality Review | 问题 + 回答 + 问题类型 + fcResult | 各竞品评分 | `analysis.qualityScores` |
| 2.4 Comparison | AIC评分 + 各竞品评分 | 差异对比表 | `analysis.comparison` |
| 2.5 Winner | 比较结果 + 加权总分 | 三选一结论 | `overallJudgment` |
| 2.6 Suggestion | 优劣判断 + AIC低分维度 | 优化建议或空 | `notes` |
| 2.7 保存 | 全部分析结果 | 合并到题目对象 | `aic.evaluation`、`competitorEvaluation` 等 |

## 3. Fact Check Workflow

```
                 ┌─────────────────────┐
                 │   输入:              │
                 │   - questionType     │
                 │   - questionText     │
                 │   - 各竞品 answer    │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   判断触发类型        │
                 │   (见下方规则表)      │
                 └──────────┬──────────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
          ▼                 ▼                 ▼
   ┌────────────┐    ┌────────────┐    ┌────────────┐
   │ 强制校验     │    │ 部分校验     │    │ 跳过校验     │
   │ (mandatory) │    │ (partial)   │    │ (skip)      │
   └──────┬─────┘    └──────┬─────┘    └──────┬─────┘
          │                 │                 │
          ▼                 ▼                 │
   ┌────────────┐    ┌────────────┐           │
   │ 全文联网搜索  │    │ 关键词提取   │           │
   │ + 时间验证   │    │ + 针对性验证  │           │
   │ + 计算验证   │    │              │           │
   └──────┬─────┘    └──────┬─────┘           │
          │                 │                 │
          ▼                 ▼                 ▼
   ┌────────────┐    ┌────────────┐    ┌────────────┐
   │ 交叉验证     │    │ 单源验证     │    │ result =    │
   │ (≥2 来源)   │    │ + 模型判断   │    │ "不适用"     │
   └──────┬─────┘    └──────┬─────┘    └──────┬─────┘
          │                 │                 │
          └─────────────────┼─────────────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   汇总 FC 结果        │
                 │   逐主张输出:         │
                 │   - claim            │
                 │   - verdict          │
                 │   - source           │
                 │   - confidence       │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   返回 fcResult      │
                 │   {                  │
                 │     required,        │
                 │     result,          │
                 │     issues[],        │
                 │     sources[],       │
                 │     confidence       │
                 │   }                  │
                 └─────────────────────┘
```

### 触发规则表

| 条件 | 触发类型 | 校验方式 |
|------|----------|----------|
| `questionType = "信息问答"` | **强制** | 全文搜索 + 每个事实主张验证 |
| `questionType = "推理分析"` | **部分** | 仅验证前提假设和引用的数据 |
| `questionType = "工具类"` + 翻译 | **部分** | 抽查关键术语翻译 |
| `questionType = "工具类"` + 总结 | **部分** | 检查是否遗漏关键信息点 |
| `questionType = "工具类"` + 计算 | **强制** | 重新计算验证 |
| `questionType = "创作生成"` | **跳过** | 无客观事实标准 |
| 回答含具体数字/百分比 | +强制 | 验证数字准确性 |
| 回答含时间（日期/星期/距今） | +强制 | 时间计算验证 |
| 回答含人名/地名/机构名 | +强制 | 拼写和对应关系验证 |
| 回答含法律/医疗建议 | +强制 | 交叉验证 + 标注风险 |
| 回答为空 | **跳过** | 无法校验 |

### Fact Check 输出结构

```
fcResult = {
  required:    "mandatory" | "partial" | "skip",
  result:      "通过" | "未通过" | "无法验证" | "不适用",
  issues: [
    {
      claim:      "回答中的具体主张",
      verdict:    "正确" | "错误" | "无法确定",
      source:     "https://..." | null,
      confidence: "高" | "中" | "低"
    }
  ],
  sources: [
    {
      url:   "https://...",
      title: "来源标题",
      type:  "权威网站" | "百科" | "学术" | "新闻" | "官方"
    }
  ],
  summary: "一句话总结本次校验结果"
}
```

## 4. Quality Review Workflow

```
                 ┌─────────────────────┐
                 │   输入:              │
                 │   - questionType     │
                 │   - questionText     │
                 │   - 竞品名称列表      │
                 │   - 每个竞品的 answer │
                 │   - fcResult (如有)   │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   确定权重矩阵        │
                 │   根据 questionType   │
                 │   查表获取 7维权重     │
                 └──────────┬──────────┘
                            │
                            ▼
         ┌──────────────────────────────────────┐
         │        对每个回答者评分                   │
         │        (AIC + Competitor1 + ... + N)  │
         │                                       │
         │  ┌─────────────────────────────┐      │
         │  │  对每个维度独立评分:           │      │
         │  │                              │      │
         │  │  1. 阅读回答全文              │      │
         │  │  2. 针对当前维度评估           │      │
         │  │  3. 写评分理由 (comment)      │      │
         │  │  4. 打 1–5 分               │      │
         │  │  5. 如果权重=0，score=0       │      │
         │  │      comment="不适用"          │      │
         │  └─────────────────────────────┘      │
         │                                       │
         │  维度顺序:                             │
         │  ① Completeness   ② Accuracy          │
         │  ③ Professionalism ④ Structure        │
         │  ⑤ Usability     ⑥ Naturalness       │
         │  ⑦ Creativity                         │
         └──────────────────┬───────────────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   计算加权总分        │
                 │                      │
                 │   totalScore =        │
                 │   Σ(dim × weight)    │
                 │   × 20               │
                 │   / Σ(weight)        │
                 │                      │
                 │   满分 100            │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   输出 qualityScores  │
                 │   {                  │
                 │     aic: {...},      │
                 │     competitors: {   │
                 │       "Ask AI": {...}│
                 │     }                │
                 │   }                  │
                 └─────────────────────┘
```

### 评分执行策略

**执行方式**：
- 使用 LLM 进行维度评分（非规则引擎）。
- 对每个回答者 × 每个问题，调用一次评分。
- 如果 `fcResult.result = "未通过"`，Accuracy 维度自动扣至 ≤2 分。

**评分 Prompt 关键要素**（供实现时参考）：
1. 提供 1 分和 5 分的锚定示例，防止评分偏移。
2. 要求先写理由，再打分（理由→分数）。
3. 注入 Fact Check 结果，确保评分考虑事实准确性。
4. 对权重为 0 的维度，直接返回 `{ score: 0, comment: "不适用" }`，不消耗 LLM 调用。
5. 所有竞品使用相同的 Prompt 模板，确保可比性。

### 评分输出结构

```
qualityScores = {
  "aic": {
    totalScore: 85,
    dimensions: {
      completeness:    { score: 4, comment: "..." },
      accuracy:        { score: 5, comment: "..." },
      professionalism: { score: 4, comment: "..." },
      structure:       { score: 3, comment: "..." },
      usability:       { score: 5, comment: "..." },
      naturalness:     { score: 4, comment: "..." },
      creativity:      { score: 0, comment: "不适用" }
    }
  },
  "competitors": {
    "Ask AI":     { totalScore: 82, dimensions: {...} },
    "ChatSmith":  { totalScore: 78, dimensions: {...} }
  }
}
```

## 5. Comparison Workflow

```
                 ┌─────────────────────┐
                 │   输入:              │
                 │   - AIC 的 7维评分   │
                 │   - 每个竞品的 7维评分│
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   对每个竞品:         │
                 │   (Ask AI,           │
                 │    ChatSmith, ...)   │
                 └──────────┬──────────┘
                            │
                            ▼
         ┌──────────────────────────────────────┐
         │   逐维度比较 AIC vs 当前竞品             │
         │                                       │
         │   for each dimension in 7 dimensions: │
         │                                       │
         │     AIC.score > 竞品.score + 1        │
         │       → AIC 此维度领先                 │
         │                                       │
         │     竞品.score > AIC.score + 1        │
         │       → 竞品此维度领先                 │
         │                                       │
         │     |AIC.score - 竞品.score| ≤ 1      │
         │       → 此维度持平                     │
         └──────────────────┬───────────────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   汇总比较结果        │
                 │                      │
                 │   aicWins: [...]     │
                 │   competitorWins: {  │
                 │     "Ask AI": [...], │
                 │     "ChatSmith": [...│
                 │   }                  │
                 │   tie: [...]         │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   生成比较总结        │
                 │   1–2 句话自然语言    │
                 │   描述 AIC vs 竞品    │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   输出 comparison    │
                 │   对象               │
                 └─────────────────────┘
```

### 比较规则

| 规则 | 说明 |
|------|------|
| 领先阈值 | 分差 ≥ 2 分才算领先。差 1 分视为持平（避免过度敏感） |
| 逐维比较 | 7 个维度逐一比较，不只看总分 |
| 多竞品分离 | 每个竞品独立与 AIC 比较，不混淆 |
| 权重感知 | 高权重维度的领先/落后在 summary 中优先提及 |
| 备注 | 权重为 0 的维度（即不适用维度）自动归入 `tie`，不参与比较 |

### 比较输出结构

```
comparison = {
  aicWins:          ["准确性", "专业度"],
  competitorWins: {
    "Ask AI":       ["结构清晰度", "语言自然度"],
    "ChatSmith":    []
  },
  tie:              ["实用性", "内容完整性"],
  summary: "AIC 在准确性和专业度上领先。Ask AI 在结构清晰度和语言自然度上表现更好。实用性方面两者持平。"
}
```

## 6. Winner Decision Workflow

```
                 ┌─────────────────────┐
                 │   输入:              │
                 │   - AIC totalScore   │
                 │   - 各竞品 totalScore │
                 │   - fcResult         │
                 │   - comparison       │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   特殊情况检查        │
                 │   (优先级从高到低)    │
                 └──────────┬──────────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
          ▼                 ▼                 ▼
   ┌────────────┐    ┌────────────┐    ┌────────────┐
   │ AIC 的      │    │ 存在竞品     │    │ 无特殊      │
   │ FC 未通过?   │    │ 回答为空?    │    │ 情况        │
   │             │    │             │    │             │
   │ YES →       │    │ YES →       │    │ → 进入      │
   │ "竞品更优"   │    │ 该竞品不计入  │    │ 常规判断    │
   └──────┬─────┘    │ 比较         │    └──────┬─────┘
          │          └──────┬─────┘           │
          │                 │                 │
          └─────────────────┼─────────────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   常规判断            │
                 │                      │
                 │   找出最优竞品总分:    │
                 │   maxCompScore =      │
                 │   max(各竞品总分)     │
                 │                      │
                 │   计算分差:            │
                 │   diff = AIC总分       │
                 │        - maxCompScore │
                 └──────────┬──────────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
          ▼                 ▼                 ▼
   ┌────────────┐    ┌────────────┐    ┌────────────┐
   │ diff > 3    │    │ -3≤diff≤3  │    │ diff < -3   │
   │             │    │             │    │             │
   │ AIC 领先    │    │ 无明显差异   │    │ 竞品领先     │
   │ → "AIC更优" │    │ → "平局"    │    │ → "竞品更优" │
   └────────────┘    └────────────┘    └────────────┘
```

### 判断优先级

| 优先级 | 条件 | 结果 | 说明 |
|--------|------|------|------|
| 1 (最高) | AIC 的回答 Fact Check 未通过 | `竞品更优` | 事实准确性是底线，不通过则直接判定 |
| 2 | AIC 回答为空 | `竞品更优` | 无回答无比较 |
| 3 | 所有竞品回答均为空 | `AIC更优` | 唯一有效回答 |
| 4 | diff > 3 | `AIC更优` | AIC 明显领先 |
| 5 | -3 ≤ diff ≤ 3 | `平局` | 分差在阈值内 |
| 6 (最低) | diff < -3 | `竞品更优` | 竞品明显领先 |

### 阈值说明

- 阈值 = **3 分**（满分 100）。
- 设定理由：小于 3 分的差异在实际使用中几乎感知不到，视为平局更客观。
- 如果未来需要更敏感的判断，阈值可调整为 2 或 1。但初次设计以 3 分为准。

```
                          │   或落后竞品 ≥2 的维度 │
                          └──────────┬──────────┘
                                     │
                                     ▼
                          ┌─────────────────────┐
                          │   生成具体建议        │
                          │   每条建议包含:       │
                          │   - 针对哪个维度      │
                          │   - 具体改进方向      │
                          │   - 优先选取高权重    │
                          │     的低分维度        │
                          └──────────┬──────────┘
                                     │
                                     ▼
                          ┌─────────────────────┐
                          │   去重 + 优先级排序   │
                          │   最多 3 条建议      │
                          └──────────┬──────────┘
                                     │
                                     ▼
                          ┌─────────────────────┐
                          │   输出 notes         │
                          │   (文本字符串)        │
                          └─────────────────────┘
```

### 建议生成规则

| 规则 | 说明 |
|------|------|
| 源头 | 仅从 AIC 评分 ≤ 2 的维度或 comparison 中 AIC 落后的维度中选取 |
| 数量 | 最多 3 条。少于 3 个问题时有多少写多少 |
| 优先级 | 高权重维度 > 低权重维度。多题共性问题 > 单题问题 |
| 表述 | 建设性、可执行、面向产品改进，而非"回答不好" |
| 去重 | 如果连续多题出现同一维度的低分，合并为一条通用建议 |

### 建议分类速查

| 低分维度 | 典型建议方向 |
|----------|-------------|
| Completeness | "补充关键信息点" / "检查是否遗漏用户问题的某一方面" |
| Accuracy | "增加数据来源引用" / "对时间/数字类内容进行核实" |
| Professionalism | "使用更专业的术语" / "加深分析深度" |
| Structure | "增加标题分段" / "在长回答开头提供摘要" |
| Usability | "输出可直接使用的格式" / "给出具体可操作的步骤" |
| Naturalness | "优化中文表达的自然度" / "减少翻译腔" |
| Creativity | "增加多样性表达" / "提供多角度视角" |

## 8. Question Loop

```
                 ┌─────────────────────┐
                 │   输入:              │
                 │   questions[] 数组   │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   初始化             │
                 │   index = 0         │
                 │   results = []       │
                 │   total =            │
                 │     questions.length │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   index < total ?    │
                 └──────────┬──────────┘
                            │
              ┌─────────────┴─────────────┐
              │ YES                       │ NO
              ▼                           ▼
   ┌─────────────────────┐     ┌─────────────────────┐
   │ 取出 questions[idx]  │     │ 所有题目分析完成       │
   │                     │     │ 进入 Daily Summary    │
   │ 执行:               │     │ (见 §9)              │
   │ - Fact Check        │     └─────────────────────┘
   │ - Quality Review    │
   │ - Comparison        │
   │ - Winner Decision   │
   │ - Suggestion        │
   │                     │
   │ 保存本题分析结果     │
   │ results.push(...)   │
   │                     │
   │ index = index + 1   │
   └──────────┬──────────┘
              │
              └────────────────────────┐
                                       │
                                       ▼
                              (回到判断 index < total)
```

### Loop 行为说明

| 行为 | 说明 |
|------|------|
| **执行顺序** | 严格按 `questionIndex` 顺序 1→N，不并行 |
| **独立性** | 每道题的分析完全独立，不参考前一题的结果（Daily Summary 阶段才跨题分析） |
| **错误处理** | 单题分析失败不中断整个 Loop。失败题目标注 `analysis.error`，继续下一题 |
| **进度日志** | 每完成一题输出 `[Analysis] Question 3/5 done — AIC更优` 格式的日志 |
| **终止条件** | `index >= questions.length` |

## 9. Daily Summary Workflow

```
                 ┌─────────────────────┐
                 │   触发条件:          │
                 │   Question Loop 完成 │
                 │   所有题分析完毕      │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   Step 9.1           │
                 │   统计 win/loss      │
                 │                      │
                 │   遍历所有题:         │
                 │   overallJudgment    │
                 │   = "AIC更优" → +1  │
                 │   = "竞品更优" → +1  │
                 │   = "平局"    → +1  │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   Step 9.2           │
                 │   汇总维度表现        │
                 │                      │
                 │   计算 AIC 在所有题目  │
                 │   的 7 维平均分       │
                 │                      │
                 │   找出:              │
                 │   - 最高分维度 →      │
                 │     strengths[]      │
                 │   - 最低分维度 →      │
                 │     weaknesses[]     │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   Step 9.3           │
                 │   竞品洞察            │
                 │                      │
                 │   对每个竞品:         │
                 │   - 其在哪些维度领先  │
                 │   - 其在哪些题目表现好 │
                 │   - 其总体水平如何    │
                 │                      │
                 │   生成 1–2 句概述     │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   Step 9.4           │
                 │   生成优化建议        │
                 │                      │
                 │   汇总所有题的 notes  │
                 │   去重 + 优先级排序   │
                 │   提取 TOP 3          │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   Step 9.5           │
                 │   生成整体评价        │
                 │                      │
                 │   综合 win/loss      │
                 │   + 维度表现         │
                 │   + 竞品对比         │
                 │                      │
                 │   写 100–200 字总结  │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │   输出 dailySummary  │
                 │   对象               │
                 └─────────────────────┘
```

### Daily Summary 生成规则

| 字段 | 生成方式 | 长度限制 |
|------|----------|----------|
| `overallAssessment` | LLM 基于统计数据 + 维度表现综合生成 | 100–200 字 |
| `strengths` | AIC 平均分 ≥ 4 的维度，最多 3 条 | 每条 5–15 字 |
| `weaknesses` | AIC 平均分 ≤ 2.5 的维度，或 多题 comparison 中落后竞品的维度，最多 3 条 | 每条 5–15 字 |
| `competitorInsights` | 每个竞品 1–2 句概述其今日特点 | 每条 20–50 字 |
| `winLossSummary` | 纯计数统计。如 `"5 道题中，AIC 在 3 道题上明显更优..."` | 自动生成 |
| `recommendations` | 汇总所有题 `notes`，去重，取最重要的 3 条 | 每条 10–30 字 |

### 输出校验规则

| 校验项 | 规则 | 不通过处理 |
|--------|------|-----------|
| 所有题有分析结果 | `questions[].analysis` 不为空 | 标记缺失题号，写入 `analysis.error` |
| `overallJudgment` 值合法 | 仅允许 `AIC更优` / `竞品更优` / `平局` | 写入 `"分析失败"` + 错误日志 |
| `dailySummary` 完整 | 所有顶层字段不为 undefined | 缺失字段写入 `"N/A"` |
| 评分范围 | `score` 在 0–5 之间 | 截断：>5 → 5，<0 → 0 |
| `totalScore` 范围 | 0–100 | 重新计算 |

```
analysis_result_{YYYY-MM-DD}.json

analysis_result_2026-07-05.json
```

```
1.  读取 today.json
2.  校验 JSON 结构
3.  提取 Session 对象
4.  ┌─ Question Loop ─────────────────────────────────────┐
    │                                                     │
    │  for each question in questions:                    │
    │                                                     │
5.  │    读取 questionType → 确定权重矩阵                  │
6.  │    判断是否需要 Fact Check → 执行/跳过              │
7.  │    ┌─ Quality Review ──────────────────────────┐    │
    │    │ for each 回答者 (AIC + 每个竞品):          │    │
    │    │   7维度独立评分 → 计算加权总分              │    │
    │    └───────────────────────────────────────────┘    │
8.  │    ┌─ Comparison ──────────────────────────────┐    │
    │    │ for each 竞品:                             │    │
    │    │   逐维度比较 AIC vs 竞品                    │    │
    │    └───────────────────────────────────────────┘    │
9.  │    执行 Winner Decision                               │
10. │    执行 Suggestion (条件触发)                         │
11. │    保存本题分析结果                                   │
    │                                                     │
    └─────────────────────────────────────────────────────┘
12. 汇总 win/loss 统计
13. 汇总维度平均分
14. 生成竞品洞察
15. 汇总优化建议 → TOP 3
16. 生成 overallAssessment
17. 组装 analysis_result.json
18. 输出校验
19. 写入文件
20. ✅ 完成
```

## 附录 B：错误处理策略

| 场景 | 处理方式 |
|------|----------|
| today.json 文件不存在 | 报错退出，输出明确提示 |
| JSON 格式错误 | 报错退出，提示第几行有问题 |
| questions 数组为空 | 报错退出，提示无题目 |
| 单题 Fact Check 超时 | 标记 `fcResult.result = "无法验证"`，继续评分 |
| 单题评分 LLM 调用失败 | 重试一次。仍失败则标记 `analysis.error`，跳过该题继续下一题 |
| 所有题评分都失败 | 报错退出，不输出空文件 |
| Daily Summary 生成失败 | 用纯统计数据填充 `dailySummary`，不阻塞输出 |
| 写入文件权限不足 | 报错退出，提示检查目录权限 |
