# Collector 使用流程

## 产品目标

Collector 的产品目标是让每天负责 AI Chat 竞品测试的人员，能够基于当天的 `Today's Benchmark Session`，按竞品顺序高效记录测试问题、回答文本、截图和竞品元信息，并最终导出标准 JSON（`today.json`）。

Collector 只负责数据采集，不进行任何回答质量分析、优劣判断或报告生成。

## 用户角色

- 竞品测试人员：每天接收测试任务，按竞品完成 AI Chat 竞品数据采集。
- 目标是让测试人员集中在手机端测试和数据录入工作，减少来回切换，确保信息完整、可恢复。

## 每日使用场景

每天早晨或测试开始前，测试人员会先在 Prompt 网站筛选出当天的 `Today's Questions`，并确认当天需要测试的竞品列表。

随后，测试人员使用 Collector：

1. 导入当天的 `Today's Questions`，创建 `Today's Benchmark Session`
2. 确认当天的竞品列表
3. 按竞品逐个完成所有问题的回答和截图采集
4. 在每个竞品所有问题完成后补录该竞品的模型与免费次数信息
5. 随时中断后恢复到上次未完成的位置
6. 手动导出 `today.json`
7. 同步 `today.json` 到电脑，供 Analysis 模块消费

## 完整操作流程

### 1. Today's Questions 导入 / Session 创建

- 在 Prompt 网站筛选 `Today's Questions`。
- 将问题列表导入 Collector；如果当前未实现自动同步，使用手动导入方式。
- Collector 基于导入内容创建当天的 `Today's Benchmark Session`。
- `Session` 包含：日期、Today's Questions、当天所有竞品、当前采集状态、已录入内容。
- 输出：创建好当天的 Session，进入全天数据采集准备阶段。

### 2. 打开 Collector 并确认当天 Session

- 打开 Collector 应用或页面。
- 验证当天 `Today's Benchmark Session` 是否已创建。
- Collector 显示当天 Session 的基本信息：日期、问题数量、竞品数量、当前完成进度。
- 输出：确认 Session 已建立，准备开始采集。

### 3. 确认竞品列表

- 测试人员确认当天需要测试的竞品，如 AIC、Ask AI、ChatSmith、ChatOn、Nova 等。
- Collector 列出当前 Session 中的竞品，并允许调整顺序或删减/新增竞品。
- 输出：当前竞品顺序确定，后续按竞品顺序采集。

### 4. 首页整体完成进度

- Collector 首页展示当天 Session 的整体进度，例如：
  - `Today's Benchmark`
  - `Completed: 2 / 5 Competitors`
- 每个竞品同时显示自己的完成状态：未开始、进行中、已完成、跳过。
- 这样测试人员打开 Collector 后，能立即知道今天已经做到哪里。

### 5. 按竞品顺序开始录入

Collector 以“竞品”为单位组织流程。

#### 5.1 进入第一个竞品

- 显示竞品名称
- 显示该竞品对应的 `Today's Questions`（通常 5 个问题）
- 显示该竞品当前的完成进度
- 输出：进入竞品数据录入阶段

#### 5.2 对当前竞品完成所有问题采集

对于当前竞品的每个问题，依次录入：

- 问题文本（由任务提供，通常已预置于 Session）
- 竞品回答文本
- 竞品回答截图（必须上传，对应每个问题）

每个问题录入完成后，Collector 自动保存当前问题的数据。

输出：当前竞品问题数据保存到 Session，会话状态更新。

#### 5.3 当前竞品所有问题完成后，补录元信息

- 当前竞品下所有问题完成后，填写该竞品的：
  - 使用模型
  - 免费次数
- 该信息属于竞品级别元信息，不再按问题重复填写。
- 输出：该竞品的元信息补录完成，当前竞品准备标记为已完成。

#### 5.4 标记当前竞品完成

- 当前竞品所有问题和元信息录入完成后，Collector 将该竞品标记为“已完成”。
- 输出：竞品完成状态更新，准备切换到下一个竞品。

### 6. 异常处理流程

如果当前竞品出现以下情况，允许测试人员先跳过该竞品：

- 网络问题
- 免费次数限制
- App 崩溃
- 无法完成测试

Collector 应支持：

- `Skip`：暂时跳过该竞品，记录其状态为“跳过/待补录”
- `稍后继续`：保留当前竞品数据，后续可以继续完成剩余问题

异常处理时，Collector 应记录：

- 当前竞品状态
- 已完成的问题数量
- 未保存的问题或未上传截图
- 异常原因说明

输出：保留未完成状态，后续可继续当前竞品或切换到下一个竞品。

### 7. 如果当天竞品数量可变，继续按竞品顺序录入

- 无论竞品数量多少，Collector 都按照当前 Session 内的竞品顺序逐个处理。
- 只有当前竞品所有问题和元信息完成后，才切换到后续竞品。
- 如果某个竞品跳过，后续仍可返回继续补录。

### 8. 处理完所有竞品后完整检查

- Collector 提供总览，显示：
  - 竞品总数
  - 已完成数量
  - 进行中数量
  - 跳过/未完成数量
- 测试人员可检查每个竞品是否存在遗漏的回答、截图或元信息。
- 输出：采集完成度确认，准备导出。

### 9. 导出 `today.json`

- 在所有竞品录入完成后，用户主动点击导出 `today.json`。
- Collector 将当前 Session 的完整数据写成标准 JSON 格式，文件名为 `today.json`。
- 输出：`today.json` 生成，供 Analysis 模块读取。

### 10. 同步到电脑

- 导出完成后，测试人员将 `today.json` 同步到电脑。
- 目前该步骤可以手动完成，例如通过手机传文件、云盘或本地传输。
- 输出：电脑端得到 `today.json`，供 Analysis 模块继续处理。

### 11. Analysis 阅读与后续处理

- Analysis 模块读取同步到电脑的 `today.json`。
- Analysis 继续自动分析、生成 Excel、生成总结。
- 这个步骤不在 Collector 负责范围内，但构成完整闭环。

## 每个步骤的输入与输出

| 步骤 | 输入 | 输出 |
|---|---|---|
| Today's Questions 导入 | `Today's Questions` 列表 | 创建 `Today's Benchmark Session` |
| 打开 Collector | 当日 Session | Session 基本信息与竞品进度 |
| 确认竞品列表 | 当天竞品清单 | 确定采集顺序 |
| 进入竞品录入 | 当前竞品、5 条问题 | 当前竞品采集会话 |
| 录入每个问题 | 回答文本、截图 | 当前问题保存、状态更新 |
| 补录竞品元信息 | 使用模型、免费次数 | 当前竞品元信息保存 |
| 标记竞品完成 | 当前竞品已完成 | 进入下一个竞品 |
| 异常跳过 | 跳过原因、未完成状态 | 记录竞品异常状态 |
| 导出 JSON | 完整 Session 数据 | 生成 `today.json` |
| 同步到电脑 | `today.json` | 电脑端可用文件 |

## 自动保存机制

- Collector 在每个问题录入后自动保存本次 Session 数据，无需手动保存。
- 自动保存内容包括：当前 Session、当前竞品、当前问题、已录入回答、截图路径、竞品元信息、竞品状态。
- 即使当前竞品尚未完成，数据也会实时保存。
- 自动保存覆盖当前会话状态，避免重复输入。

## 中断恢复机制

- 用户可随时中断，例如切换手机测试应用、休息、网络异常或关闭 App。
- Collector 记录最后的 Session 进度，并在下次打开时恢复至上次未完成位置。
- 恢复内容包括：
  - 当前 Session
  - 当前竞品与其完成状态
  - 当前竞品已完成的问题数量
  - 当前竞品仍待填写的问题
  - 已上传截图与回答
- 如果某个竞品被标记为 `Skip`，Collector 在恢复时仍保留该状态，并提供继续补录入口。

## 导出流程

- 用户完成所有竞品录入后，主动点击导出 `today.json`。
- Collector 从当前 Session 读取完整数据，生成 JSON 文件。
- 导出的 JSON 必须符合 `docs/data_model.md` 定义的标准。
- 导出结果保存为 `today.json`，并显示导出成功提示。

## Flow Summary

1. Prompt 网站筛选 `Today's Questions`
2. 导入 `Today's Questions` 到 Collector
3. Collector 创建 `Today's Benchmark Session`
4. 打开 Collector，确认当天 Session
5. 确认竞品列表，确定采集顺序
6. 首页显示整体完成进度
7. 进入第一个竞品，按问题依次录入回答和截图
8. 当前竞品所有问题完成后，补录模型和免费次数
9. 标记当前竞品完成
10. 如有异常，可选择 Skip 或稍后继续
11. 继续下一个竞品，重复步骤 7-10
12. 全部竞品录入完成后检查状态
13. 手动导出 `today.json`
14. 同步 `today.json` 到电脑
15. Analysis 模块读取 `today.json` 并继续处理
